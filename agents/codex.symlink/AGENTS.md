# AGENTS

## Principles

* Prefer simple, direct solutions.
* Do not over-engineer.
* Make the smallest reasonable change that solves the problem.
* Favor readability and maintainability over cleverness.
* Reuse existing patterns and conventions before introducing new ones.
* When requirements are ambiguous, state your assumptions instead of guessing.
* Use only the ASCII hyphen-minus (`-`) in prose. Never use em dashes or en dashes.

## Code Quality

* Keep functions and modules small, cohesive, and focused on a single responsibility.
* Use descriptive, intention-revealing names.
* Prefer explicit, type-safe code whenever the language supports it.
* Handle errors explicitly and fail with clear, actionable messages.
* Remove dead code, unused imports, and unnecessary complexity.
* Keep the codebase consistent with the surrounding style unless there is a compelling reason not to.
* Add comments only to clarify ambiguous or non-obvious intent. Do not comment code that is already self-explanatory or merely restates what the code does
